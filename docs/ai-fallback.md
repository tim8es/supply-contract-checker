# AI Fallback: проверка неизвестных условий прямо в реестре

Прототип работает без LLM, ключей и внешних запросов. ИИ подключается
**только по нажатию «✦ Проверить через ИИ» рядом с «Нет данных»**
в таблице «Действующие условия». Кнопка показывается **для каждого «Нет данных»**: суммы, срока
поставки и ежедневной ставки неустойки. Даже неподписанный договор и
противоречие в документах можно исследовать через ИИ, но найденный текст
**не становится юридически действующим значением** без выполнения правил
подписания, вступления в силу и проверки конфликтов.

## Как использовать

1. Откройте приложение, загрузите свои TXT либо нажмите **«Пример для ИИ»**
   рядом с **«Открыть пример»** в панели загрузки (также работает `?ai-demo=1`).
2. Если поле не найдено, нажмите **«✦ Проверить через ИИ» под «Нет данных»**.
3. При первом запуске откроются «⚙ Настройки ИИ»: укажите URL полного
   OpenAI-совместимого endpoint (с `/chat/completions`), модель и ключ.
4. Повторно нажмите кнопку рядом с нужным полем. Текст **только
   выбранного договора и запрашиваемого условия** передаётся провайдеру.
5. Подтверждённый по первоисточнику кандидат появится в той же ячейке
   с меткой «ИИ · проверить» и кнопкой просмотра цитаты. Если положение
   юридически спорное (например, договор не подписан или есть дубликат),
   оно останется «Нет данных» с отдельным объяснением и кнопкой
   просмотра найденного ИИ фрагмента. Если модель ничего не нашла,
   причина тоже отображается **в ячейке**, без отдельной панели.
6. Другие отсутствующие поля проверяются отдельным нажатием.

На исходном наборе STN-101 и STN-102 уже найдены правилами, а STN-103
не содержит согласованной суммы — ИИ не должен её придумывать.

**Отдельный AI-набор** состоит из четырёх полноформатных вымышленных
договоров (промышленное оборудование, медицинское оснащение, мебель
для офиса и лабораторные расходники), подписанного допсоглашения
и письма поставщика. Это **шесть других TXT-файлов в `examples/`**,
не влияющих на исходные три договора из `documents/`.

| Договор | Что локальные правила уже определяют | Что проверять через ИИ |
|---|---|---|
| NLP-204 | Есть подписанный основной договор | Стоимость всей партии, обязательный срок передачи |
| NLP-205 | Сумма с учётом подписанного вступившего в силу допсоглашения; ставка неустойки | Дата фактической передачи оборудования |
| NLP-206 | Срок по договору; письмо о переносе показано отдельно | Совокупная цена партии |
| NLP-207 | Срок передачи | Цена отсутствует в предоставленном приложении; ИИ должен ответить «нет данных» |

В документах есть оглавленные разделы, ответственность, реквизиты,
отдельные авансы и другие числа, которые **не являются ценой договора**.
Вызовы API выполняются **только по кнопке в ячейке** и проходят проверку
цитат. Результаты конкретной реальной модели заранее не гарантируются.
Полный перечень и эталонный смысл документов — в
[`examples/README.md`](../examples/README.md).

## Локальное сохранение настроек

- **Endpoint и модель** автоматически сохраняются в `localStorage`
  браузера (`stn.model-settings.v1`) и восстанавливаются после перезагрузки.
- **API-ключ** по умолчанию остаётся только в поле ввода открытой вкладки.
- При включении «Сохранять API-ключ на этом устройстве» ключ записывается
  в `localStorage` **без шифрования**; отключение флажка удаляет
  его сохранённую копию. Режим годится только для доверенного личного
  профиля, не для общего/рабочего компьютера.
- Кнопка «Удалить настройки и AI-результаты» очищает сохранённые настройки,
  поле ключа и текущие результаты модели.
- TXT-документы, результаты анализа и история договоров **не сохраняются
  в localStorage**. Ключ не экспортируется в JSON приложения.
- При запрете доступа к localStorage приложение продолжает работать,
  но настройки остаются только в текущей вкладке.

Сайты с вредоносным скриптом, браузерные расширения и люди с доступом
к профилю могут прочитать незашифрованный ключ. Для корпоративного
приложения требуется авторизованный серверный посредник и управление
секретами. Не передавайте внешнему провайдеру конфиденциальные договоры
без разрешения организации.

## Технические и юридические ограничения

- HTTPS (или локальный HTTP на localhost), явный endpoint `/chat/completions`.
- Прямой запрос из браузера возможен **только если API допускает CORS**.
  Наличие правильного ключа не снимает этого ограничения.
- В одном нажатии передаётся не более 12 документов по 14 000 символов;
  при выборе конкретной ячейки отправляются только относящиеся к ней
  допустимые подписанные документы. Письма и неподписанные проекты
  исключаются из AI-запроса.
- Модель возвращает номер абзаца и буквальный токен суммы/даты.
  Браузер проверяет имя файла, строки, дословную цитату и значение.
  Затем **только детерминированный движок** определяет применимость
  допсоглашений и действующее значение.
- Проверка цитаты **не гарантирует правильную правовую трактовку**.
  Любой кандидат модели помечается для проверки специалистом.
- API может стоить денег; никаких платных API для базовой функциональности
  и CI не требуется.

## Проверки

`npm test` запускает тесты сохранения/удаления настроек, приватности
ключа, точечной передачи одного поля и одного договора, отклонения
недостоверных цитат, подписанных изменений и сетевых ошибок. Chrome E2E
проверяет реальную интерактивность с **имитацией API**, включая сохранение
и отзыв разрешения на хранение ключа.

Ни CI, ни опубликованная демонстрация не доказывают качество конкретной
реальной модели. Benchmark Precision/Recall рассчитан **без AI**.

## Проверка источника без автоматического перехода

Кнопка **«↗ Проверить источник»** теперь раскрывает значение, файл,
строки и дословную цитату **только в «ИСТОЧНИК И ДОКАЗАТЕЛЬСТВО»**.
Исходный документ не переключается и не прокручивается при таком нажатии.
Нужен полный текст — нажмите отдельную команду
**«Показать в исходном тексте ↗»** в инспекторе.
